# 静默匹配

启用 SQLite，配置官方输入和真实 QQ OneBot `observe` 输入。初次部署使用 `matching.mode: shadow`，在管理端查看候选和冲突，确认真实样本后再开启 `auto`。

- 配对使用可比较的普通群文本。统一行尾并去掉首尾空白后，所有非空文本均可参加匹配。匹配队列只保留内容指纹，消息大小遵循接入协议的帧上限。不同消息可连续发送，2 秒默认窗口只比较同一消息在两端的时间。候选在窗口收敛后执行双向唯一性检查。
- 已确认群优先限制搜索范围。未知群默认需要三条独立头像验证记录，来自至少两位发送者。测试群只有一个用户时，可在管理端先手动绑定两个群 OpenID 到同一真实群号。
- 通过 AppID 和 OpenID 获取官方头像，通过真实 QQ 号获取观察头像。下载限制为指定 HTTPS 主机、2 MiB 和 1024×1024 像素。SHA-256 辅助确认相同字节，pHash 默认汉明距离阈值为 4。过滤低信息图和已发现的跨 QQ 近似头像。采样得到的占位头像可以配置到 `default_avatar_phashes`。下载失败或头像不可用时保留已有进度。
- 同一官方事件与观察消息在同一 AppID 的同类证据中最多各计一次。用户默认需要三条有效消息，证据有效期为 24 小时。竞争证据冻结候选。管理员可以人工确认、修正或撤销，真实 ID 填 0 表示撤销。
- 网关根据观察 Bot 的群列表、群消息和进退群事件确认观察范围。已映射的群有观察 Bot 时可以登记待绑定身份。群号未知时，首次通过头像验证的消息配对才会登记。已绑定用户在没有观察 Bot 的群里仍按业务路由处理。

影子模式产生候选并继续使用虚拟号。切到自动模式后，下一条有效证据会重新检查阈值。绑定成功时删除待绑定记录，保留真实身份和原始 OpenID 的关联。旧编号保留在内部用于反查已转发的消息。身份映射和匹配列表支持按来源群、QQ 号和 OpenID 检索。
